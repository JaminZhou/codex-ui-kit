## Entry and ownership

A locally generated, two-page `design-spec.pdf` was dropped onto an empty
New chat Composer through trusted CDP input. Clicking the attachment opened
a **right-hand workspace tab**, not an immersive dialog or a centered card.
No message was submitted. The PDF contains only synthetic verification copy.
Its byte count and SHA-256 are recorded so subsequent content comparisons can
use the same document, retained in the private playground at
`playgrounds/codex-app/fixtures/documents/design-spec.pdf`. The research check
verifies the fixture hash. The PDF skill was used to generate and visually verify
the two pages; no private document or proprietary page content was copied.

The tab strip occupies the first 46px. The PDF section begins beneath it,
with a 40px toolbar and one independent document scroller. The observed wide
panel is 590.828125px at 1180x820. This is the sampled panel size, **not a
claim about a universal default width**; workspace width is host-controlled.

The toolbar owns the filename without its extension, Previous page, the
page indicator, Next page, Annotate, zoom, Download, and the split external
Open action. Download and external opening were observed but not invoked.
The pages are rendered canvases with document-owned text/content layers.
There is no generic PDF badge/subtitle card inside the preview body.

## Verified transitions

- Page 1 disables Previous; Page 2 disables Next. Paging scrolls the same
  document container rather than replacing the workspace tab.
- The zoom menu has exactly `25%`, `50%`, `100%`, `150%`, `200%`, and
  `Zoom to fit`. Choosing 150% increases the page extent inside the owned
  scroller; fitting returns to 91% in the sampled wide panel.
- Annotate changes to Annotating and grows from 32px to 106.75px. Toggling
  it off restores the original control. No mark or comment was created.
- Enter full screen expands the **workspace pane** to 1180px and fit becomes
  190%; it is not a claim about entering macOS full-screen mode. Restoring
  returns to the prior side-panel width and 91% fit.
- Changing the Renderer viewport to 720x680 hides/unmounts the side panel.
  The draft PDF remains. Clicking it again opens a 344.671875px side panel
  with 50% fit, a 40px toolbar, and one 594px-high scroller. The title is
  clipped while the paging and host controls remain available.
- Compact paging reaches page 2. Closing the tab preserves the attachment;
  reopening starts at page 1 with scrollTop 0.
- Removing the exact synthetic attachment leaves zero preview nodes, zero
  matching attachment buttons, and an empty Composer. The original user
  Codex window was not navigated or resized.

The header resolves to system UI fonts at 13px/20px, weight 430, with a

## Evidence boundary and implementation correction

The CDP Browser window lookup reports `Browser window not found`, including
when given the selected target ID. Width changes therefore use Renderer
emulation and are explicitly **not native-window resize acceptance**.

The centered-card fixture introduced in #293 is useful as a generic component
regression, but it does not reconstruct this observed PDF workspace. The next
implementation must compose the tab strip, a page-aware toolbar, one document
scroller, pane expansion, narrow hide/reopen, and close/attachment ownership.
It must then pass independent replay/CDP, Electron, and owned-region product
pixel comparisons before Browser/Electron inventory statuses are promoted.

Loading, malformed/password-protected PDF, error recovery, actual annotation
editing, download, native external-app launch, multiple document tabs, light
theme, and non-PDF document formats remain open. The new observation advances
runtime reachability for the PDF and artifact-shell slice only; it does not
complete either surface family or the delivery plan.
