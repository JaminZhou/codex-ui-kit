## Native project-menu change

The project action trigger still renders as a 24×24 button with
`aria-haspopup="menu"`, but 26.818 no longer inserts a DOM `role="menu"`.
`app.asar` and the live React owner both resolve the project action provider to
`window.electronBridge.showContextMenu`. The bridge object and method are
frozen in the Renderer.

The sampled pinned local project supplies six selectable actions and three
separators in this exact order:

1. `unpin-project` — Unpin
2. `edit-project` — Edit
3. `project-actions-separator`
4. `reveal-project-folder` — Reveal in Finder
5. `create-permanent-worktree` — Create permanent worktree
6. `project-chat-actions-separator`
7. `archive-project-threads` — Archive chats
8. `project-remove-separator`
9. `remove-project` — Remove project

`mark-project-threads-read` remains a conditional action immediately before
Archive chats when the project has unread activity. The current baseline
contract accepts only those two ordered variants.

For the native observation, the system pointer was moved to the exact CDP
trigger coordinate before invoking the frozen bridge. Quartz then reported one
new ChatGPT-owned layer-101 window at 221×187, anchored at the project action
button. A system Escape event closed it and returned the Renderer trigger to
`aria-expanded="false"`. The full-screen capture and profile remain local-only
because surrounding navigation contains user-owned text.

This supersedes the previous 214.05px DOM project menu and its DOM focus
contract. The independent web playground still renders the older DOM replica,
so `app.sidebar-project-actions-menu` is deliberately `partial_legacy` until a
native-menu visual replica and Browser/Electron/region gates are updated.
